# Doodle Arena: Word Selection & Gameplay State Security

## 1. Security Overview & Threat Model

In real-time multiplayer drawing games, the primary attack vector is client-side state inspection: malicious users opening browser Developer Tools, inspecting WebSocket traffic, or querying client state trees (Redux/React DevTools) to extract the secret word and cheat on guesses.

Doodle Arena implements an authoritative, zero-trust backend state projection model that mathematically prevents clients from discovering the secret word or hidden category metadata prior to legitimate round completion.

---

## 2. Server-Authoritative State Filtering (`toClientRoomState`)

The backend never broadcasts raw internal game state to connected clients. Instead, every state broadcast passes through `RoomManager.toClientRoomState(room, isSpectator, forPlayerId)`:

```typescript
// server/game/RoomManager.ts
const isDrawer = forPlayerId === room.currentDrawerId;
const canSeeWord =
  isDrawer ||
  room.phase === 'ROUND_RESULT' ||
  room.phase === 'MATCH_RESULT' ||
  (isSpectator && !room.settings.isPrivate);

const isEasy = (room.settings.difficulty || '').toUpperCase() === 'EASY';
const isCategoryVisible =
  isEasy ||
  isDrawer ||
  room.phase === 'ROUND_RESULT' ||
  room.phase === 'MATCH_RESULT';

return {
  code: room.code,
  ...,
  clue: room.clue,
  category: isCategoryVisible ? room.category : '',
  categoryVisible: isEasy,
  wordLength: room.secretWord.replace(/\s+/g, '').length,
  letterCount: room.secretWord.replace(/\s+/g, '').length,
  secretWord: canSeeWord ? room.secretWord : undefined,
};
```

### Security Properties:
1. **Guesser Payload Hygiene:**
   During the active `DRAWING` phase, the serialized JSON payload sent to any guesser contains `secretWord: undefined`. JSON serialization strips undefined keys entirely, ensuring the string never enters the browser memory or network interface.
2. **Category Stripping in Medium & Hard Tiers:**
   For Medium and Hard matches, `category` is replaced with `""` for guessers. Guessers receive no semantic hints, only the letter count and masked clue dashes (`_ _ _ _ _`).
3. **Targeted State Delivery:**
   State broadcasts iterate through each connected socket individually (`room.socketToPlayerId`), generating a cryptographically scoped state projection for that specific player ID. Guessers never receive the drawer's payload.

## 3. Targeted Word Selection Delivery (`word:options`)

When a turn starts, 3 options matching the room's difficulty are generated by `WordService.getRandomWordOptions(targetDiff, usedWords)`.

### Delivery Mechanism:
- The options are transmitted **exclusively to the active drawer's socket**:
  ```typescript
  const drawerSocket = this.io.sockets.sockets.get(drawer.socketId);
  drawerSocket.emit('word:options', { options: room.wordOptions, durationSeconds: 15 });
  ```
- The room at large is only informed via system message that the drawer is choosing a word.
- Other players have no socket subscriptions or payload access to the candidate options.

---

## 4. Guess Validation & Room Notification Hygiene

All guess evaluations occur authoritatively on the backend server:

1. **Backend Guess Evaluation:**
   `GuessService.evaluateGuess(rawGuess, secretWord)` normalizes the string, checks alias mappings, and calculates Levenshtein distance on the server.
2. **Notification Isolation:**
   When a player guesses correctly:
   - The guesser receives a private `guess:success` event confirming their points.
   - The room receives a `guess:correct` event containing only `playerId` and `playerName`. **The secret word is never broadcast** in this event.
   - The guess text is filtered from the public chat feed, preventing other players from reading the winning answer.
3. **Near-Miss Isolation:**
   When a guess is within a 1-character Levenshtein distance:
   - The guessing player privately receives `guess:close` ("You're close!").
   - The public chat receives a regular chat message so other players cannot deduce that a close attempt was made.
